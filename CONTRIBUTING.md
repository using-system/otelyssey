# Contributing to otelyssey

otelyssey is a marketplace of OpenTelemetry agent plugins that runs
itself: the repository validates, reviews, lists and follows the plugins
it is given. There are three ways to take part.

## Submit a plugin

Open a [plugin submission](https://github.com/using-system/otelyssey/issues/new?template=submit-plugin.yml):
one field, the URL of your plugin's `plugin.json` on GitHub. The
repository reads everything else from that file and from your
repository, installs the plugin on the hosts, judges its relevance to
OpenTelemetry and its categories, and answers on the issue. Your plugin
needs a public GitHub repository, a `plugin.json` in the
[Agent Plugins](https://agent-plugins.org/) format, and OpenTelemetry as
its subject: instrumentation, the Collector, a backend that ingests
OpenTelemetry telemetry, or observability on top of it. Competing plugins
are all listed; the marketplace never arbitrates between them.

Once listed, the repository follows your releases every night: your
latest `X.Y.Z` or `vX.Y.Z` tag when it carries the plugin, otherwise a
new `version` in `plugin.json` on your default branch. A release that
does not validate or install on the hosts stays unlisted, the previous
one remains, and a `release-follow` issue says why.

To withdraw a plugin, say so in a
[bug report](https://github.com/using-system/otelyssey/issues/new?template=bug_report.yml);
the maintainer deletes the record in a pull request. That is the only
hand edit the store ever gets: never open a pull request against
`.store/` or the generated files, the pipeline writes them.

## Report a bug, ask for a feature

Use the issue forms:
[bug report](https://github.com/using-system/otelyssey/issues/new?template=bug_report.yml)
for something the marketplace does wrong (an intake that refuses a valid
plugin, a page that renders badly, a host that fails to install),
[feature request](https://github.com/using-system/otelyssey/issues/new?template=feature_request.yml)
for a new host, a new rule, a better page. State what you confirmed with
a command and its output, and what you only observed once. Questions and
open-ended ideas go to
[Discussions](https://github.com/using-system/otelyssey/discussions).

A problem in a listed plugin belongs to that plugin's repository, not
here.

## Contribute code

The rules are in [AGENTS.md](AGENTS.md), written for coding agents and
for people alike; contributing through a coding agent is the expected
path, and you remain responsible for what your agent commits, opens or
comments under your name. In short:

- **An issue first.** Every pull request references an existing issue
  (`Closes #N`); open the issue when none exists.
- **A branch, never `main`.** `type/short-description`. Commit messages
  and pull request titles follow
  [Conventional Commits](https://www.conventionalcommits.org/),
  `type(scope): lowercase imperative description`; no `!` or
  `BREAKING CHANGE` marker without discussing it first. One logical
  change per pull request. Everything committed is in English.
- **Run what CI runs** before opening the pull request:

  ```bash
  uvx ruff@0.16.4 check scripts tests && uvx ruff@0.16.4 format --check scripts tests
  uv run --no-project --with pytest pytest -q
  python3 -m scripts.store --check
  python3 -m scripts.build --check
  ```

  A change to `.github/workflows/*.md` also needs `gh aw compile`
  (the version `ci.yml` pins) and its outputs committed.
- **Two reviews before a push.** A code reviewer and a security
  reviewer, sub-agents in parallel on the diff, until both report
  nothing left to fix; AGENTS.md says how.
- **The store is the pipeline's.** `.store/` records are written by the
  admission and the nightly; `marketplace.json`, the catalogs,
  `hermes-pack.yaml`, `marketplace/` and the README's plugin list are
  generated by `scripts/build.py`; never edit them by hand.
- **The README is the shop window**, not a specification: short,
  didactic, pleasant to read. The details live in the design spec under
  `docs/` and on the plugin pages.
- **Scripts are standard library only**, Python 3.11+, run as modules
  from the repository root, and print their result and nothing else.

## Security

Vulnerabilities go through
[private reporting](https://github.com/using-system/otelyssey/security/advisories/new),
never a public issue; the scope is in [SECURITY.md](SECURITY.md).
